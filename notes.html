Agent Scaffold / Engineering Notes

从配置表到可运行的 Agent。

这组笔记记录 Agent Scaffold 的完整构建路径：定义 Agent 配置，装配模型、工具和工作流，再通过会话接口把能力交给真实用户使用。

Java 17Spring AIGoogle ADKDDDMCPSkills

目录

需求与架构 配置与装配 工作流与执行 工具、会话与 Skills

Foundation

先定义一种可以被装配的 Agent。

起点不是单次对话，而是一套可描述 Agent、模型、工具和执行方式的结构。需求分析和系统架构先把边界、模块与配置模型固定下来。

00

脚手架需求分析

明确 Agent 配置、模块编排与执行框架的产品边界。

01

系统架构设计

拆分基础能力、脚手架、Agent 框架、模块编排与工程结构。

02-03

工程初始化与 API 测试

建立 Java 工程基础，并验证 Spring AI、LangChain4j 与 Google ADK 的接入边界。

04-05

配置表与装配域

用 YAML 与结构化对象承载 Agent 的定义，为后续节点装配准备统一输入。

Assembly

把配置逐层变成运行时对象。

装配链路从 AI API、ChatModel、Agent 到 AgentWorkflow 逐步向下构建。每个节点只处理自己的职责，并把结果交给下一个节点。

06

AiApiNode

根据配置创建模型服务连接，为后续模型调用提供统一入口。

07

ChatModelNode

组合模型参数与工具回调，形成可被 Agent 使用的 ChatModel。

08-09

AgentNode 与 AgentWorkflowNode

创建单体 Agent，并将多个 Agent 组织为可执行的工作流。

12

加载与使用验证

验证 YAML 配置能被完整装配并由运行服务正确加载。

核心思路配置不是静态文档。它是 Agent 工程的输入语言，装配链路负责把它翻译成真实的模型、工具与执行对象。

Workflow

让 Agent 从一次回答走向一段流程。

Runner 负责把具体 Agent 交给运行时。Sequential、Parallel 与 Loop 将执行模式显式化，让流程可以按配置组合和调整。

10

Loop、Parallel、Sequential

定义循环、并行和串行三种基础工作流结构。

11

RunnerNode

将选定的 Agent 与运行入口连接，形成实际的执行起点。

13

增强 RunnerNode

继续完善运行节点的装配能力与验证链路。

14

增强 AgentWorkflowNode

使工作流节点可以承接更复杂的 Agent 编排需求。

Capabilities

工具、会话和 Skills 让工程进入真实场景。

MCP、回调插件、多模态、会话服务与 UI 接口把脚手架从框架能力延伸到实际交互。Skills 则用领域步骤增强工具调用的可靠性。

15-16

本地 MCP 与回调插件

将本地工具与自定义回调接入 Agent 的工具集合。

17

多模态能力排查

通过分块验证与源码调试，定位并修复多模态调用链问题。

18-20

会话服务与 UI 对接

实现服务层、触发层和界面联调，使 Agent 能力以对话形式交付。

21

Skills 增强装配

支持从资源或目录加载技能书，并与 MCP 工具一起进入 ChatModel 的回调集合。

Skills 与 MCP 不是替代关系。工具提供可执行的外部能力，Skills 补充完成任务所需的领域步骤和上下文，两者共同提高 Agent 在真实场景中的可靠性。
